## Overview

MoodMuse is a single-page creative web app built for the AWS Builder Center
Weekend Challenge (deadline: Aug 17, 2026, 1:00 PM PT). A user types a short
mood or scene prompt and the app returns an original poem and a matching mood
board image, displayed together on one screen.

---

## User Stories

### Core (implemented)

**US-1 — Generate poem and image**
As a user, I want to type a short mood or scene prompt and receive a 4–8 line
original poem and a matching mood board image so that I have a creative visual
and textual response to my mood in one place.

Acceptance criteria:
- The prompt input accepts free text up to 500 characters
- Clicking "Generate" (or pressing Ctrl/Cmd+Enter) submits the prompt
- The response includes a poem of 4–8 lines generated by Amazon Bedrock Nova Micro
- The response includes a 512×512 PNG image generated by Amazon Bedrock Nova Canvas
- Poem and image appear together on a single screen without a page reload
- The button is disabled and shows a loading indicator while the request is in flight

**US-2 — Inline error feedback**
As a user, I want to see a clear error message if something goes wrong so that
I understand what happened without a confusing browser alert or CORS error.

Acceptance criteria:
- Empty prompt submission shows an inline validation message before any API call is made
- API errors (4xx, 5xx, network failure) display an inline error banner — no `alert()` calls
- The output area is hidden while an error is shown
- The error message is human-readable (not a raw AWS error code)

**US-3 — Character counter**
As a user, I want to see how many characters I have remaining so that I know
when I'm approaching the prompt limit.

Acceptance criteria:
- Counter displays `{n} / 500` and updates on every keystroke
- Counter turns orange at 400 characters, red at 490

## Out of Scope (explicit non-requirements)

The following were considered and deliberately excluded to meet the weekend
deadline:

| Feature | Reason excluded |
|---|---|
| User accounts / auth | Scope; no multi-user requirement |
| Save / history | Scope; app is stateless by design |
| Sharing / social | Scope |
| CloudFront / HTTPS on S3 | S3 website endpoint HTTP is sufficient for demo |
| DynamoDB | No persistence needed |
| Multi-page flows | Single creative job only |
| Amplify hosting | Vanilla JS + S3 is zero-build and faster to ship |
| Rate limiting | Not needed at demo volume |

---

## Constraints

- All AWS services in `us-east-1` — Nova Canvas is only available in
  `us-east-1`, `eu-west-1`, and `ap-northeast-1`; `us-east-1` was chosen
  because there is no data residency requirement for this build, not
  because it offers broader model coverage than the other two regions
- App is stateless; no PII is stored or transmitted beyond the prompt text
- Everything must stay within AWS Free Tier for hosting (Lambda, API Gateway,
  S3) — Bedrock inference is not free tier (see Cost Notes)
- HTTP API hard integration timeout cap is 30s and cannot be raised; image
  generation must reliably complete within that window
